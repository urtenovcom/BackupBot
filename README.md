# 📦 BackupBot

**BackupBot** — надежное, автономное и простое решение для резервного копирования Docker-проектов на VPS с потоковым шифрованием и отправкой архивов в Telegram.

Бэкапы организованы так, что их легко найти в Telegram по проекту, серверу и дате с помощью структурированных хештегов. Приложение не требует веб-интерфейса, баз данных вне SQLite и сторонних облачных хранилищ (S3 и др.).

## 1. Архитектура и особенности

- **Автономность каждого VPS**: каждый сервер запускает свой легковесный контейнер со своим `server_id` и независимым списком проектов.
- **Один бот на весь парк серверов**: все VPS отправляют резервные копии через один токен Telegram-бота в один приватный канал или группу.
- **Только исходящие запросы**: не используется polling или webhook. Серверы не слушают входящие подключения и полностью изолированы от внешних сетевых команд.
- **Штатные инструменты дампов**: базы данных (PostgreSQL, MySQL, MariaDB) выгружаются штатными утилитами (`pg_dump`, `mysqldump`) внутри целевых контейнеров через `docker exec`. Файлы работающей базы «на горячую» не копируются.
- **Жизненный цикл и хуки**: поддержка `pre_backup` и `post_backup` действий (например, перевод проекта в режим обслуживания и обратный запуск). Хук `post_backup` гарантированно выполняется даже при ошибке бэкапа.
- **Потоковое шифрование age**: на VPS хранится **только публичный ключ** получателя. Даже при полной компрометации сервера злоумышленник не сможет расшифровать прошлые бэкапы. Приватный ключ хранится локально у администратора.
- **Разбиение на части (Chunking)**: если архив превышает лимит (по умолчанию 45 МБ), он автоматически разбивается на части (`.part01`, `.part02`, ...). Каждая часть снабжается SHA-256 и подписью.
- **Защита от пересечений**: файловые блокировки (`flock`) исключают одновременный запуск бэкапа одного проекта из cron и CLI.
- **Локальный журнал в SQLite**: отслеживает статус каждого запуска и message_id отправленных частей. При сбое сети повторный запуск досылает только те части, которые ещё не были доставлены.

## 2. Официальные ограничения Telegram Bot API

Перед реализацией и эксплуатацией проверены актуальные официальные спецификации Telegram Bot API:

| Параметр | Официальный лимит | Реализация в BackupBot |
| :--- | :--- | :--- |
| **Максимальный размер документа (sendDocument)** | **50 MB** для стандартного Cloud Bot API | По умолчанию `split_size_mb: 45` (гарантирует запас до 50 МБ) |
| **Длина подписи к медиафайлу (caption)** | **1024 символа** (после парсинга) | Автоматический контроль и безопасное усечение до 1024 символов |
| **Длина текстового сообщения (sendMessage)** | **4096 символов** | Контроль и усечение логов ошибок до безопасного размера |
| **Ограничение частоты (Rate Limits)** | HTTP 429 Too Many Requests | Автоматическое считывание параметра `retry_after` и пауза |

> [!WARNING]
> Лимит 2000 МБ (2 ГБ) относится к обычным пользовательским Telegram-клиентам и Premium-пользователям. Официальный облачный сервер Bot API (`https://api.telegram.org`) строго ограничивает отправку документов ботами в **50 МБ**. BackupBot безопасно разбивает большие архивы на части любого заданного размера (по умолчанию 45 МБ).

## 4. Создание Telegram-бота и настройка чата/канала

### Шаг 1: Создание бота
1. Откройте Telegram и найдите официального бота [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot`.
3. Введите имя бота (например, `Company Backup Bot`).
4. Введите юзернейм бота (должен заканчиваться на `bot`, например `company_vps_backup_bot`).
5. Скопируйте полученный токен (вида `1234567890:ABCdefGHIjklMNOpqrsTUVwxyz123456789`) и вставьте его в `.env` в переменную `TELEGRAM_BOT_TOKEN`.

### Шаг 2: Создание канала или группы
1. Создайте в Telegram **приватный канал** или **приватную супергруппу** (например, `Server Backups`).
2. Добавьте созданного бота в администраторы канала с правом **«Публикация сообщений»** (`Post messages`).

### Шаг 3: Получение ID чата (TELEGRAM_CHAT_ID)
- **Способ 1 (через бота @userinfobot или @raw_data_bot)**:
  Добавьте [@raw_data_bot](https://t.me/raw_data_bot) в канал/чат, он выведет JSON с `chat_id` (для каналов начинается с `-100...`). После этого удалите бота из канала.
- **Способ 2 (через браузер)**:
  1. Опубликуйте в канале любое тестовое сообщение.
  2. Перейдите по ссылке:
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
  3. В ответе найдите поле `"chat":{"id": -100xxxxxxxxxx}`.
  4. Запишите этот ID в `.env` в переменную `TELEGRAM_CHAT_ID`.

## 5. Генерация ключей шифрования age

Для шифрования используется современный инструмент [age](https://github.com/FiloSottile/age) (X25519 + ChaCha20-Poly1305).

> [!IMPORTANT]
> Создавайте пару ключей **на своем доверенном рабочем компьютере**, а НЕ на сервере VPS!

### Генерация:
```bash
# Установка age на macOS / Linux:
# brew install age   (macOS)
# apt install age    (Ubuntu/Debian)

age-keygen -o my_backup_key.txt
```

В файле `my_backup_key.txt` появятся две строки:
```
# Public key: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
AGE-SECRET-KEY-1...
```

- **Публичный ключ (`age1...`)**: укажите в `.env` (`AGE_PUBLIC_KEY=age1...`) на всех серверах VPS.
- **Приватный ключ (`AGE-SECRET-KEY-1...`)**: надежно сохраните в менеджере паролей или на защищенном диске. **Никогда не копируйте его на VPS!**

## 6. Конфигурация (config.yaml и .env)

### Файл `.env`
```dotenv
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz123456789
TELEGRAM_CHAT_ID=-1001234567890
AGE_PUBLIC_KEY=age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
MY_WEBSITE_DB_PASSWORD=secret_postgres_pass
```

### Файл `config.yaml`
```yaml
server_id: "vps_01"  # Только латиница, цифры и подчеркивания

telegram:
  bot_token: "${TELEGRAM_BOT_TOKEN}"
  chat_id: "${TELEGRAM_CHAT_ID}"
  api_url: "https://api.telegram.org"
  timeout_seconds: 180
  max_retries: 5

storage:
  work_dir: "/var/tmp/backupbot"
  state_db: "/var/lib/backupbot/backupbot.db"
  min_free_space_mb: 500

projects:
  - id: "my_website"
    name: "Корпоративный сайт"
    schedule: "0 3 * * *"            # Каждый день в 03:00
    timezone: "Europe/Moscow"
    paths:
      - "/opt/my_website/compose.yaml"
      - "/opt/my_website/data/uploads"
    volumes:
      - "my_website_static"
    databases:
      - type: "postgres"
        container: "my_website_db_1"
        db_name: "production_db"
        user: "postgres"
        password: "${MY_WEBSITE_DB_PASSWORD}"
        extra_args: ["--clean", "--if-exists"]
    exclude:
      - "*.log"
      - "*.tmp"
      - "cache/*"
    hooks:
      pre_backup: "echo 'Режим обслуживания включен'"
      post_backup: "echo 'Режим обслуживания выключен'"
    encryption:
      enabled: true
      recipient: "${AGE_PUBLIC_KEY}"
    retention_days: 7
    split_size_mb: 45
```

## 7. Настройка нескольких VPS (Multi-VPS)

Если у вас несколько серверов (например, `vps_01`, `vps_02`, `db_cluster`):

1. **Один токен бота и один канал**: вам не нужно создавать нового бота для каждого VPS. Все серверы используют одинаковые `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
2. **Уникальный `server_id`**: на каждом VPS в `config.yaml` задается свой `server_id` (например, `server_id: "vps_de_01"`).
3. **Поиск в Telegram**: в общем канале бэкапы фильтруются штатными Telegram-хештегами:
   - Все копии конкретного проекта: `#project_my_website`
   - Все копии с определенного сервера: `#server_vps_01`
   - Копии за конкретный день: `#date_2026_11_07`
   - Сообщения об ошибках: `#backup_error`

## 8. Интерфейс командной строки (CLI)

Все команды можно запускать как локально в Python, так и через `docker compose run`:

### 1. Проверка конфигурации
```bash
docker compose run --rm backupbot validate-config
```
Выведет статус валидации, список проектов, часовые пояса и параметры шифрования.

### 2. Список настроенных проектов
```bash
docker compose run --rm backupbot list-projects
```

### 3. Ручной запуск резервного копирования
```bash
# Бэкап конкретного проекта
docker compose run --rm backupbot backup --project my_website

# Последовательный бэкап всех проектов
docker compose run --rm backupbot backup --all
```
*(При возникновении ошибки команда завершается с ненулевым exit code `1`).*

### 4. Просмотр истории и статуса запусков
```bash
docker compose run --rm backupbot status
```
Выведет таблицу последних бэкапов из SQLite с датами, стадиями, размерами и количеством частей.

### 5. Запуск демона-планировщика
```bash
docker compose run --rm backupbot run-scheduler
```
*(Используется по умолчанию в compose.yaml).*

## 9. Безопасность и Docker Socket

### Доступ к Docker Socket (`/var/run/docker.sock`)
В `compose.yaml` монтируется `/var/run/docker.sock`. Зачем это нужно?
1. **Выгрузка баз данных**: для выполнения `docker exec -i <container> pg_dump ...` без открытия портов БД (5432, 3306) наружу и без необходимости хранить базы на хосте.
2. **Резервное копирование Docker Volumes**: для чтения именованных томов контейнеров.

> [!WARNING]
> Доступ к Docker socket равносилен правам root на хосте. Поэтому:
> - BackupBot не слушает внешнюю сеть и не принимает команды из Telegram.
> - Не используйте сторонние непроверенные образы.
> - Если вы хотите ограничить доступ, можно использовать [docker-socket-proxy](https://github.com/Tecnativa/docker-socket-proxy) с разрешением только эндпоинтов `POST /containers/{id}/exec`, `POST /exec/{id}/start` и запретом изменения остальных параметров хоста.

### Защита секретов
- Логгер BackupBot автоматически маскирует токен бота, пароли баз данных и секретные параметры (`********`) в консоли и журналах.
- Приватный ключ `age` никогда не передается и не создается на сервере.

## 10. Надёжность, дозагрузка и журнал состояний

1. **Гарантия At-Least-Once**:
   При нестабильном канале связи возможна ситуация, когда Telegram принял файл, но сетевой ответ прервался по таймауту. В этом случае BackupBot может повторно передать эту же часть. При восстановлении дубликаты легко отсекаются по SHA-256.
2. **Дозагрузка только неотправленных частей**:
   Если архив состоял из 5 частей, 3 части успешно загрузились, а на 4-й произошел сбой сети, SQLite сохраняет `message_id` первых трёх частей. При следующем запуске первые 3 части повторно не загружаются.
3. **Хранение локальных копий (Retention)**:
   - Успешно отправленные архивы хранятся на диске `retention_days` дней, после чего автоматически удаляются.
   - **Неотправленные или аварийные архивы автоматически НЕ удаляются**, чтобы администратор мог забрать их вручную.
4. **Контроль диска**:
   Перед началом бэкапа проверяется наличие свободного места (`min_free_space_mb`). Если места недостаточно, операция прерывается и в Telegram отправляется уведомление об ошибке.
5. **«Доставлено в Telegram» ≠ «Восстановление проверено»**:
   Успешная доставка означает только сохранность файлов в облаке Telegram. Регулярно проводите учебные восстановления по инструкции ниже!

## 11. Пошаговая инструкция восстановления (Disaster Recovery)

> [!NOTE]
> Автоматическая перезапись рабочего проекта категорически не рекомендуется. Всегда восстанавливайте бэкап в **новую директорию** или тестовое окружение!

### Шаг 1: Поиск и скачивание в Telegram
1. В строке поиска Telegram введите хештег проекта и дату, например:
   `#project_my_website #date_2026_11_07`
2. Скачайте все части архива (если копия была разделена):
   - `vps_01__my_website__2026-11-07_03-00-00__abc123.tar.gz.age.part01`
   - `vps_01__my_website__2026-11-07_03-00-00__abc123.tar.gz.age.part02`
3. Поместите их в отдельную рабочую папку, например `~/restore_target/`.

### Шаг 2: Проверка контрольных сумм SHA-256
Сверьте контрольную сумму каждой скачанной части со значением из подписи к сообщению в Telegram:
```bash
# macOS:
shasum -a 256 *.part*

# Linux:
sha256sum *.part*
```
Хеши должны посимвольно совпадать.

### Шаг 3: Сборка единого зашифрованного архива
Если файл был разделен на части:
```bash
cat *.part* > backup_assembled.tar.gz.age
```
*(Если файл был один без суффикса `.part*`, этот шаг пропускается).*

### Шаг 4: Расшифровка с помощью приватного ключа age
Используйте ваш файл приватного ключа (`my_backup_key.txt`), созданный на этапе настройки:
```bash
age -d -i my_backup_key.txt -o backup_restored.tar.gz backup_assembled.tar.gz.age
```

### Шаг 5: Распаковка архива
```bash
mkdir -p extracted && tar -xzf backup_restored.tar.gz -C extracted/
cd extracted/
```

### Шаг 6: Проверка манифеста
В корне распакованного каталога находится `manifest.json`:
```bash
cat manifest.json
```
Убедитесь в корректности проекта, времени создания и состава:
```json
{
  "format_version": "1.0",
  "backup_id": "20261107_030000_abc123",
  "server_id": "vps_01",
  "project_id": "my_website",
  "composition": [...]
}
```

### Шаг 7: Восстановление файлов и базы данных
1. **Восстановление файлов и compose-проекта**:
   ```bash
   cp -r files/* /opt/my_website_restored/
   ```
2. **Восстановление Docker Volume**:
   ```bash
   # Создание нового целевого тома
   docker volume create my_website_static_restored

   # Копирование данных из бэкапа в новый volume
   docker run --rm -v my_website_static_restored:/target -v $(pwd)/volumes/my_website_static:/source alpine cp -r /source/. /target/
   ```
3. **Восстановление базы данных**:
   Запустите контейнеры проекта и восстановите дамп:
   ```bash
   # Для PostgreSQL:
   cat dumps/postgres__my_website_db_1__production_db.sql | docker exec -i my_website_db_1 psql -U postgres -d production_db

   # Для MySQL / MariaDB:
   cat dumps/mysql__my_mysql_1__app_db.sql | docker exec -i my_mysql_1 mysql -u root -p${DB_PASSWORD} app_db
   ```

## 12. Тестирование

Проект покрыт автоматическими тестами сценариев (41 тест):
- Генерация и форматирование подписей и хештегов Telegram;
- Проверка лимита длины caption в 1024 символа;
- Проверка шаблона имен файлов;
- Потоковое разделение на части и безошибочная обратная сборка;
- Полный цикл шифрования и расшифровки age;
- Обработка сбоев дампа БД и сетевых ошибок Telegram (включая HTTP 429 `retry_after`);
- Дозагрузка только неподтвержденных частей при прерывании отправки;
- Механизм взаимных блокировок (`flock`);
- Полный сквозной цикл (бэкап проекта -> разбиение -> мок Telegram -> склейка -> дешифровка -> проверка контрольных сумм и содержимого).

### Запуск тестов:
```bash
source .venv/bin/activate
pytest -v
```
